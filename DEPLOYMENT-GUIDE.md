# Deploying Clarity

Three pieces: a Postgres database, the API (Render), and the web app (Vercel).
Allow about 45 minutes the first time. Run `./check.sh` first and deploy only if it passes.

## 0. Put the code on GitHub

```bash
git init && git add . && git commit -m "Clarity"
# create an empty PRIVATE repository on github.com, then:
git remote add origin https://github.com/<you>/clarity.git
git push -u origin main
```

Keep the repository private. The `.gitignore` already excludes databases, `.env` files and the local signing key.

## 1. Database

The API needs a Postgres database that persists.

- **Do not use SQLite on Render's free tier.** Its disk is wiped on every redeploy, restart and spin-down, so every journal would be lost. The app refuses to start in production with SQLite for this reason.
- **Render's free Postgres is deleted 30 days after creation** (with a 14-day grace period to upgrade) and has no backups. Fine for a throwaway test, not for real users' journals.
- Use a Postgres you intend to keep: a paid Render Postgres, or another managed Postgres provider. Check the provider's current free-tier terms and backup policy before choosing.

Copy the connection string. It looks like `postgresql://user:password@host/dbname` (keep any `?sslmode=require` suffix).

## 2. API on Render

1. Render dashboard -> New -> Blueprint -> pick your repository. Render reads `render.yaml`.
2. When asked for the unset variables, enter:
   - `DATABASE_URL`: the connection string from step 1
   - `CORS_ORIGINS`: leave a placeholder such as `https://example.com` for now (you set the real value in step 4)
   - `SIGNUP_CODE`: a phrase you will give to invited users, e.g. `alpha-7fd2`. Leave empty only if you want open signups.
3. Deploy. `SECRET_KEY` is generated by Render; `ENVIRONMENT` is already `production`.
4. Open `https://<your-api>.onrender.com/health`. It should return `{"status":"healthy"}`.

If the service fails to start, the log line beginning `Refusing to start in production:` says exactly which setting is missing.

Free-tier behaviour to expect: the API sleeps after 15 minutes without traffic and takes about a minute to wake. The app shows "Can't reach the server. It may be waking up" during that minute.

## 3. Web app on Vercel

1. Vercel -> Add New Project -> import the repository.
2. Root Directory: `frontend`. Framework preset: Vite (build `npm run build`, output `dist`).
3. Environment variable: `VITE_API_URL` = `https://<your-api>.onrender.com` (no trailing slash).
4. Deploy and note the URL, e.g. `https://clarity-xyz.vercel.app`.

`frontend/vercel.json` makes deep links such as `/journal` work on refresh.

## 4. Connect them

In Render -> your service -> Environment, set `CORS_ORIGINS` to the exact Vercel URL (no trailing slash; comma-separate if you add a custom domain). Save; Render redeploys.

## 5. Check the live site

- Sign up with the invite code, write an entry, pick a mood.
- Upload your own calendar export on the Calendar page and sanity-check the numbers.
- Account -> Download everything, then delete the test account.
- On your phone, repeat the signup.

## Operating notes

- **Forgotten password:** there is no email reset yet. From your machine:
  `cd backend && DATABASE_URL=<production url> python -m scripts.reset_password user@example.com`
  It prints a temporary password to send to the user.
- **Backups:** turn on your database provider's backups before inviting users.
- **Schema changes:** tables are created on first start. There is no migration tool yet, so changing a table later needs a manual `ALTER TABLE` (or adding Alembic).
- **Scaling past one instance:** login rate limiting is kept in memory per instance.

## Environment variables

| Variable | Where | Required | Purpose |
|---|---|---|---|
| `ENVIRONMENT` | API | yes (`production`) | Enables startup safety checks, hides API docs |
| `SECRET_KEY` | API | yes | Signs login tokens; 32+ random characters |
| `DATABASE_URL` | API | yes | Postgres connection string |
| `CORS_ORIGINS` | API | yes | Web app URL(s), comma separated |
| `SIGNUP_CODE` | API | recommended | Invite code required to sign up |
| `VITE_API_URL` | Web | yes | API base URL |
